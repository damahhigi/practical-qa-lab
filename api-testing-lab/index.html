THINK LIKE A QA ENGINEER
What should you verify?
Use these questions to investigate your responses.

      

        
01
Status code
Compare 200 OK for GET/PUT/PATCH, 201 Created for POST, and 204 No Content for DELETE. Explore 400, 404, 405, 409 and 422 errors.

        
02
PUT vs PATCH
PUT requires all four editable fields and replaces the record. PATCH changes only the supplied fields. Confirm the id remains unchanged.

        
03
Delete and verify
After DELETE returns 204, check that the body is empty. GET the same user again: it should return 404. A refresh resets this simulator.

      

      
Stage 3: GET, POST, PUT, PATCH and DELETE are all simulated in-browser. Changes reset when the page reloads. Coming later: intentionally seeded API defects, bug reporting, feedback and progress tracking. This is not a live HTTP client.
