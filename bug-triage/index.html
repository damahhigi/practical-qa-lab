01 · BEFORE YOU BEGIN

Severity is not the same as priority.

Use the same rubric for all five reports. Consider customer harm, frequency, affected workflow, time sensitivity and whether a workaround has been verified.

01

Severity = impact

Critical: financial or security harm. High: a major user journey is broken. Medium: meaningful but limited disruption. Low: cosmetic or negligible functional impact.

02

Priority = urgency

P0: act immediately. P1: fix before a committed deadline or release. P2: plan the next cycle. P3: backlog / approved deferral.

03

Action = decision

Choose whether to stop the rollout, fix and retest before release, schedule a prioritized fix, or explicitly defer with the right approval.

QA tip: A lower-severity issue can still have high priority when a customer deadline is close. Avoid ranking bugs from severity labels alone.
