01 · QUICK CONCEPTS

Negative tests need precise evidence

A negative test is successful when the application correctly rejects invalid input. Boundary-value testing examines values at and immediately beside a requirement's limit.

01

Missing required fields

Submit an empty required field and assert the exact validation error rather than checking only that an alert appears.

02

Invalid format

Use a nonempty, malformed email value to test format validation separately from an empty-field rule.

03

Minimum − 1

If a password needs at least 8 characters, test 7 to verify rejection at the lower boundary.

04

Maximum + 1

If a password allows at most 20 characters, test 21 to verify rejection at the upper boundary.

RULES & SIMPLIFIED HTML

Registration contract

Full name: Required. Empty input → Full name is required

Email address: Required and correctly formatted. Nonempty malformed email → Enter a valid email address

Password: 8–20 characters inclusive. 7 or 21 characters → Password must be 8–20 characters

<form novalidate>
  <label>Full name <input /></label>
  <label>Email address <input /></label>
  <label>Password <input type="password" /></label>
  <button>Create account</button>
  <p role="alert">Validation message</p>
</form>

For this fictional scenario the app uses custom validation rather than browser-native validation. It does not truncate overlong passwords.
