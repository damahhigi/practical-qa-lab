01 · QUICK CONCEPTS

Check the response, not just the request

Playwright's request fixture sends HTTP requests without opening a browser page. A useful API test verifies the HTTP status and meaningful JSON data, including error responses.

01

Send a request

Use await request.get('/api/products/42') to receive an APIResponse. The request base URL must be configured in a real project.

02

Assert the status

response.status() returns a numeric status code. Check the exact expected result, such as 200 for a successful lookup.

03

Check the JSON

Read the body with await response.json() and assert relevant fields, not merely that a response exists.

04

Test a missing resource

A product that does not exist should return 404. Negative API tests verify the documented error behaviour.

EXPECTED CONTRACT

Response requirements

Successful lookup: GET /api/products/42 returns 200.

JSON body: The product has numeric id: 42 and name: "Canvas Backpack". Extra JSON fields may also appear.

Missing product: GET /api/products/9999 returns 404, not a success code.

Real execution: A test runner would need an API service and a configured baseURL.

{
  "id": 42,
  "name": "Canvas Backpack",
  "price": 49.99,
  "currency": "USD"
}

This exercise practises static code selection. A real Playwright project should also test response headers, authentication, invalid payloads and other contract rules when applicable.
