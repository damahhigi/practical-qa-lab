YOUR MISSION

Evaluate before you ship

Read the required launch gate and QA evidence. Classify the finding, choose a release action, set severity and calculate the requested metric. Then compare your evaluation with the reference answer.

All datasets, outcomes, labels and quality gates are fictional learning fixtures. No live model, external API, accounts or browser storage are used.

01 · AI EVALUATION METHOD

Make quality measurable

Decide what “good enough” means before evaluating a model. Inspect dataset provenance, compute the appropriate metric and apply explicit release blockers rather than relying on one overall score.

01

Build a trustworthy set

Include normal, boundary and adversarial cases; use independent holdout data and control for duplicate leakage.

02

Compute task-aware metrics

Use groundedness, accuracy, recall, false negatives and reviewer agreement where they fit the risk.

03

Compare slices and baselines

Check language groups, failure categories, uncertainty, label quality and changes since the last accepted version.

04

Apply release gates

Specify minimum quality, allowed regression and zero-tolerance security blockers before the decision.

Primary finding · ~45%

Identify the right evaluation defect or a justified pass.

Release decision · ~20%

Approve, block or investigate as required by the stated gate.

Severity · ~15%

Assess observed impact, not speculative downstream harm.

Calculated metric · ~20%

Enter the requested percentage. Written evidence is encouraged but not automatically scored.

Metrics reminder: Accuracy = correct / total; recall = TP / (TP + FN); observed agreement = matching ratings / all double ratings. Cohen’s κ adjusts agreement for chance. A passing aggregate score does not excuse a critical security failure.

Scope note: The module uses deterministic, invented datasets to teach evaluation reasoning, not a live-model audit or proof of real-world fairness or safety. Thresholds are case-specific training requirements, not universal AI standards.
