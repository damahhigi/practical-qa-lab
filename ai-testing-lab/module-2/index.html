Prompt & Response Testing

Same requirement, different prompts: should an AI assistant give the same answer? Compare paired prompt-and-output fixtures from Assist AI. Identify failures, judge impact, and design a stronger follow-up test.

6 paired evaluations100 pointsTest design practice
YOUR MISSION

Compare two outputs, not just one

Review the approved requirement and both prompt variations. Classify the main issue, assign a contextual severity and record evidence. You can propose a follow-up prompt to test the behavior again.

All prompts, outputs and policies are fictional, prewritten fixtures. This is a guided simulation—not a live AI evaluation. The page does not save or upload your answers. You can download your report.

01 · EVALUATION METHOD

Test behavior under prompt variation

Evaluate the underlying requirement, not a preferred wording. A different writing style can be fine; a changed decision or fabricated source may not be.

01

Set the oracle

Start with the policy and expected outcome; avoid deciding solely from fluent wording.

02

Vary one factor

Rephrase, change format, remove context or repeat a prompt while holding requirements steady.

03

Compare meaning

Check correctness, format constraints, traceable sources and whether equivalent inputs give equivalent decisions.

04

Design a retest

Record a follow-up prompt and what result would pass; real models need repeated, sampled runs.

Classification · about 70%

Identify the main observed issue, or correctly select Pass when both responses satisfy the requirement.

Severity · about 30%

Select the closest reference impact level; actual severity depends on the product context.

Evidence and retest · not auto-scored

Practise writing a convincing comparison and an improved follow-up prompt. Both appear in the report.

Why paired testing? A single correct answer does not establish reliability. Evaluate paraphrases, constraints, repeat runs and ambiguity against a stable oracle. This small fixture set demonstrates testing techniques; it does not estimate real-world failure rates.
