SQL DATA INVESTIGATION · STAGE 3

Three data-quality investigations

Each case has a stated requirement. Use the SQL editor and database explorer above to investigate the records, compare expected and actual data, then save your findings below. The investigation dataset is fictional and intentionally inconsistent.

CASE 01 · BUSINESS VALIDATION

Check order totals

Requirement: Each order total must be zero or greater. A negative total is invalid.

Start by sorting all orders by total and inspecting unusual values.

CASE 02 · REFERENTIAL INTEGRITY

Check order ownership

Requirement: Every order's customer_id must refer to a customer in the customers table.

Compare order identifiers with the customer table. Look for unmatched records.

CASE 03 · DATA UNIQUENESS

Check customer emails

Requirement: Two customer accounts must not share the same email address.

Sort the email column so repeated values appear next to one another.

Case 01 — Order totals

Expected: Order totals must be zero or greater.

Seeded defect: Order 5010 (customer 102, status paid) has total -350.

SELECT * FROM orders ORDER BY total ASC;

Case 02 — Order ownership

Expected: Every orders.customer_id refers to an existing customer.

Seeded defect: Order 5009 references customer_id 999, which is absent from customers.

SELECT * FROM customers WHERE id = 999;

Case 03 — Unique customer emails

Expected: Each customer email belongs to one account only.

Seeded defect: Customer 101 (Jane Wanjiku) and customer 107 (Mary Achieng) share jane@example.com.

SELECT id, name, email FROM customers ORDER BY email ASC;
